# M4 plan: real collectors

Status: approved to proceed without a review stop, as for M1 to M3 (Flavio asked on 2026-09-26 for M1 to M4 to be built overnight). Decisions that would normally be questions are listed under "Decisions taken without review".
Date: 2026-09-27

## Goal

Read the systems a data security team already runs, with read-only access, without calling live services in CI, and let a team add its own source as a package.

Acceptance, from the brief: contract tests pass on fixtures; an AWS integration test passes against LocalStack; a plugin created with the scaffold installs and runs without changes to the core.

## Scope

### HTTP in the SDK

A `HttpCollector` base class in `plugins/sdk/http.py`, so no plugin reimplements the hard parts:

- Timeouts (connect and read), retries with exponential backoff and jitter on connection errors, 429 and 5xx, honouring `Retry-After`.
- Pagination helpers: `Link: rel="next"` headers, cursor fields, page numbers and offsets, with a page limit and a record limit per query.
- Read-only by construction: GET only, except for a per-collector allowlist of named read actions that some APIs send as POST (AWS JSON APIs). Anything else raises before a request is sent.
- Response size limit, JSON only, no redirects to other hosts.
- An injectable transport so contract tests replay recorded fixtures. CI never calls live services.

### SSRF protection

Every outbound URL, for every collector, passes one check:

- The host must match the admin-managed allowlist (`DSEC_COLLECTOR_ALLOWED_HOSTS`, exact names or `*.suffix`). Empty means no outbound calls at all.
- The name is resolved once, and every address must be outside loopback, link-local (which covers the 169.254.169.254 metadata address), multicast, unspecified and reserved ranges, and outside the IPv6 forms of the same, including IPv4-mapped addresses. Known metadata names (`metadata.google.internal` and similar) are refused by name as well.
- The connection goes to the checked address, with the original name used for TLS verification and SNI, so DNS rebinding between check and connect does not help.
- HTTPS only, except `http://` for hosts an operator lists in `DSEC_COLLECTOR_ALLOW_HTTP_HOSTS` (for LocalStack-style test endpoints). Private ranges (10/8, 172.16/12, 192.168/16) are allowed, because internal APIs live there; the allowlist is what limits them.

### Collectors

| Plugin | Queries |
| --- | --- |
| `rest` | Config-driven: base URL, auth reference, and per query a path, parameters, a records path in the response, and a pagination style |
| `aws` | `kms_key_rotation`, `acm_certificates`, `config_rule_compliance`, `iam_access_key_age` |
| `vault` | `auth_methods`, `audit_devices`, `transit_key_versions` |
| `jira` | `issues` (JQL from config) |
| `servicenow` | `table` (table name, encoded query and fields from config) |
| `github` | `branch_protection`, `code_scanning_alerts`, `dependabot_alerts` |

Each ships its minimum read-only permissions in `required_permissions`, in `docs/collectors/<name>.md` (an IAM policy, a Vault policy, the Jira, ServiceNow and GitHub scopes), and contract tests over recorded fixtures.

AWS requests are signed with Signature Version 4, implemented with the standard library (`hmac`, `hashlib`) and tested against AWS's published test vectors.

### Scaffold

`dsec-metrics plugin new collector <name> [--directory DIR]` writes a package with `pyproject.toml` (entry point in `dsec_metrics.collectors`), a config model, a collector with one sample query, a fixture, and a contract test. A test scaffolds a plugin, makes it discoverable as an installed distribution, runs its query through the normal pipeline (redaction, hashing, storage) and runs its generated tests, with no change to the core.

### Plugin author guide

`docs/plugins.md` grows into the author guide: the scaffold, the HTTP base class, fixtures and contract tests, permissions, and the review checklist (no writes, no secrets in messages, sensitive fields declared).

## Decisions taken without review

1. HTTP goes through the standard library (`http.client`, `ssl`, `socket`), not a new dependency. The brief names no HTTP client for runtime use, and pinning connections to checked addresses is simpler with `http.client` than by patching a client library's transport.
2. AWS signing is our own SigV4 implementation instead of `boto3`, which the brief does not name and which pulls in a large dependency tree. It covers the JSON and Query APIs the four AWS queries use, and it is tested against AWS's test vectors and LocalStack.
3. The LocalStack test uses a version-pinned image from before LocalStack required an account token. If the image cannot be pulled, the test fails rather than skipping, so a missing acceptance check is visible.
4. The scaffold test makes the generated package discoverable by writing its `dist-info` metadata next to its source on `sys.path`, the same metadata `pip install` writes, rather than installing into the shared test environment.

## Risks

- A hand-written SigV4 can drift from AWS behaviour at the edges (unusual characters in paths, query encoding). The collectors only use fixed paths and simple parameters; test vectors and LocalStack cover them.
- LocalStack's coverage of AWS Config is partial. If a query cannot be exercised there, its contract test on fixtures stays and the gap is written down.
